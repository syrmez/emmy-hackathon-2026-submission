What “lowering” means here
    

  1. Read the entry name and argument order. Each .u64 parameter holds a buffer address, not a float value.
    2. 

  2. Turn the Tile schedule into a thread index and a bounds check. The guard is implicit in the Tile, not a statement in the printed IR.
    3. 

  3. Translate a Load into address arithmetic and ld.global.f32. Each float occupies four bytes.
    4. 

  4. Translate Assign(add) into add.rn.f32, then Write into stores. Our baseline splits the grouped write into two scalar stores.
    5. 



The guard in the emitted PTX
mad.lo.u32 %r5, %r0, %r1, %r2;
// gid = block index * block size + thread index
setp.ge.u32 %p0, %r5, 64;
// predicate = gid >= number of work items
@%p0 bra DONE;
// true? skip all loads, arithmetic and stores
64 is read from this IR's Tile. It is not a problem-specific constant in our compiler. Virtual register names such as %r5 are assigned by the emitter; ptxas chooses physical registers later.
